# 会话全文搜索

`/sessions` 在搜索词非空时等待输入停止 300 ms，再请求 `GET /api/sessions/search?query=...&regex=true|false&page=N`。空词立即清除搜索结果并保留原会话列表；较早请求返回后不会覆盖新搜索。结果按会话更新时间、消息顺序排列，每页最多 20 条，提供前后各 30 个 Unicode 字符的片段、所在会话、聊天端用户 ID、消息角色和发送时间。点击结果会展开对应会话，仍可使用现有标注和笔记操作。

接口要求有效管理端令牌，直接查询 PostgreSQL 的 `sessions` 与 `session_messages`，不进入旧接口的整库加载和全局写锁。普通搜索对 `%`、`_` 和反斜杠按字面匹配；正则模式使用 PostgreSQL 不区分大小写的正则语法，语法错误返回 400。搜索词上限 200 字，查询执行限制 750 ms；超时返回 408。结果按页读取，避免一次返回所有消息。当前会话仍按共享评审语义对所有已登录管理端账号可见，聊天端 `external_user_id` 不是管理端账号 ID。

本地验收命令：`npm run benchmark:session-search`。2026-10-11 在 10 核／16 GB macOS、Node 22.23.2、Docker PostgreSQL 18.6 的回环连接上，构造 1,100 个会话、11,000 条消息，各执行 30 次请求：普通搜索中位 151 ms、p95 156 ms；正则搜索中位 179 ms、p95 184 ms。测量只包含已登录后的 HTTP 搜索请求，不包含数据库建库、种子写入或页面初次加载。生产主机和实际聊天数据仍需单独测量；页面显示由用户验收。
