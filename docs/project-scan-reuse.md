# 相同 Git blob 的扫描正文复用

新扫描固定目标 commit 后，只查询**同一仓库连接**中创建时间更早、最新一份成功或部分覆盖的扫描。先前扫描保存的 `read` 文件可按 Git blob SHA 成为候选；当前树仍由 GitHub 按目标 commit 读取，文件路径、分类、排除规则及预算全部重新计算。每条候选复用前重新编码正文并核对字节大小、SHA-256、Git blob SHA-1 和当前已知密钥规则。不匹配时重新向 GitHub 读取该 blob，不把旧正文直接视为当前证据。

新下载的 blob 也按 Git 对象格式计算 SHA-1，并与当前 commit 树中的 blob SHA 对照；不一致时记为读取失败，不把正文保存为该 commit 的证据。复用数量保存在 `project_scans.reused_count`，有实际复用时记录来源 commit；旧扫描迁移后数量为 0，不伪造缓存命中。复用仍计入本次文件数与正文大小预算，但不请求对应 GitHub blob。文件删除后不在当前树中出现，因此不会从旧索引带入；重命名且正文不变时可以复用内容，但记录为当前路径。GitHub 目录请求、扫描失败与未覆盖范围仍按本次执行独立统计。

这是扫描正文缓存。目录模块分析输出的复用规则见[分析结果复用](project-analysis-cache.md)；已索引文件差异和全量重扫见[增量扫描差异](project-scan-changes.md)。
