# 项目分析任务并发与恢复

项目分析任务及尝试状态保存在 PostgreSQL。进程内按创建顺序排队，同一任务只进入本进程队列一次。项目分析与实验／评测 worker 共用管理员设置的 `concurrency_limit` 个 PostgreSQL advisory lock 名额；名额用尽时任务保持原来的 `queued` 或 `analyzing` 状态，不提前发起模型调用。服务启动及运行期间每五秒重新捡取未结束的分析任务，名额释放后继续执行。实验运行在标记为执行中之前领取同一名额，直到输出和评分写入后才释放；启动恢复仍按原任务状态规则处理。

单任务还有独立的数据库 advisory lock，防止多个进程同时执行同一任务。模型调用使用 90 秒超时，失败后任务显示原因，并由用户决定是否重试。已发出但结果未可靠入账的调用不会自动重发，以免重复计费；重启后遇到这种调用会提示结果未知。取消时更新持久状态并中止当前进程的请求；跨进程的执行在下一个状态检查时停止写入。

项目分析单进程队列目前串行；跨进程的项目分析、实验和评测运行合计最多同时占用 `concurrency_limit` 个名额。实验运行可能包含主模型和 Judge 的顺序调用，整个运行持续占用一个名额；这控制运行数，并不代表同一运行的每个供应商请求独立领取名额。调整上限不会中断已经开始的调用，降低上限后须等待原运行结束才能完全达到新值。名额由数据库会话持有，进程退出后数据库释放锁；数据库连接中断时的在途供应商调用仍须依靠原有超时与恢复规则处理。
