# 项目分析任务并发与恢复

项目分析任务及尝试状态保存在 PostgreSQL。进程内按创建顺序排队，同一任务只进入本进程队列一次。各 API 进程从管理员设置的 `concurrency_limit` 中领取一个 PostgreSQL advisory lock 名额；名额用尽时任务保持原来的 `queued` 或 `analyzing` 状态，不提前发起模型调用。服务启动及运行期间每五秒重新捡取未结束任务，名额释放后继续执行。

单任务还有独立的数据库 advisory lock，防止多个进程同时执行同一任务。模型调用使用 90 秒超时，失败后任务显示原因，并由用户决定是否重试。已发出但结果未可靠入账的调用不会自动重发，以免重复计费；重启后遇到这种调用会提示结果未知。取消时更新持久状态并中止当前进程的请求；跨进程的执行在下一个状态检查时停止写入。

项目分析单进程队列目前串行，跨进程最多同时运行 `concurrency_limit` 个项目分析任务。该名额尚未与实验执行 worker 共用一个全局池，管理员设置的数值分别约束两类执行；统一跨模块并发治理仍需后续处理。调整上限不会中断已经开始的调用。
