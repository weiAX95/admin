# 项目分析输入边界

项目分析只读取固定 commit 的公开仓库文件。扫描器在读取正文前排除 `.env`、密钥文件、`.npmrc`、`.pypirc`、`.netrc`、`.aws`、`.kube`、`.ssh`、Terraform state／tfvars 等路径及依赖、构建、二进制文件；读取后若命中已知凭据格式，整份文件标为 `sensitive_content`，不保存正文。分析器再次检查旧扫描记录，避免历史上已入库的敏感路径或正文被选作模型证据。

项目目标、需求基线文字和版本化需求正文也会检查已知凭据格式。新建项目或需求版本时拒绝这类输入；已有旧记录在提交分析和后台恢复时再次检查，命中后停止模型调用并返回 `SENSITIVE_INPUT`。项目所有者可在列表“编辑目标”中修正目标与未版本化的需求基线标记；版本化需求正文只通过新增不可改写的版本修订。修改只影响后续分析，已有报告保留提交时的快照；保存时比较打开弹窗时的原值和需求版本，避免覆盖并发修改。模型输入只包含通过筛选的少量文件、行号、项目目标及需求文本，受文件数、字符数和模块数预算约束；仓库正文被标明为待分析数据，不作为系统指令。报告证据必须与本次选中的文件行一致。

这是已知格式过滤，不是对任意秘密的零漏检保证。扫描结果中的 `excluded` 和 `unscanned` 数量须与报告一起阅读；被排除的文件没有参与分析。公开仓库即使已对外可读，仍应避免在项目目标或需求正文中粘贴私密材料。模型调用审计只保存“仓库代码输入已省略”的占位内容，不记录完整提示词。
