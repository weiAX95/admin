# 增量扫描差异与全量重扫

每次扫描仍从目标 commit 的 Git 树建立当前文件索引。服务把它与同一仓库、同一分支中较早且最近一份成功或部分覆盖扫描的索引比较，保存基线扫描和 commit。路径相同且 Git blob SHA 不同记为修改；仅新索引出现记为新增；仅旧索引出现记为删除；路径变化而 Git blob SHA 完全相同记为重命名。配对按路径稳定排序。重命名同时修改正文时无法仅凭 blob SHA 确认身份，本阶段显示为删除与新增。两个分支指向同一 commit 时可分别保留进行中扫描，避免跨分支互相占用扫描名额；索引约束见[146 迁移](../db/migrations/146_project_scan_branch_isolation.sql)。

差异只比较两次**已索引**的路径；任一侧为部分覆盖时，页面明确提示不能把结果视为完整仓库差异。排除和未读取的文件仍可参与路径／Git SHA 比较，但不会成为代码正文证据。新扫描不继承已删除路径，报告里的证据必须来自当前扫描。

勾选“全量重扫”后，扫描不读取旧正文缓存，仍遵守所选文件数、总字节数及单文件上限。使用该扫描生成的分析不跨报告复用旧模块输出；失败重试仍可复用本作业已成功且经过校验的调用，避免重复计费。全量重扫依然保存与前一份扫描的差异，便于核对。相同 commit 同时只能有一个进行中的扫描；请求不同模式时返回冲突，而不悄悄合并。

当前目录级输入指纹会让变化模块重新分析、未变化模块复用；跨模块综合调用总是重新执行。JS／TS 一跳相对导入的补读范围见[增量分析影响范围](project-analysis-impact.md)。其他语言、别名和多跳依赖尚未覆盖，`TODOLIST.md` 的 14.9 整项仍待统一验收。
