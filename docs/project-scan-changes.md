# 增量扫描差异与全量重扫

每次扫描仍从目标 commit 的 Git 树建立当前文件索引。服务把它与同一仓库、同一分支中较早且最近一份成功或部分覆盖扫描的索引比较，保存基线扫描和 commit。路径相同且 Git blob SHA 不同记为修改；仅新索引出现记为新增；仅旧索引出现记为删除；路径变化而 Git blob SHA 完全相同记为重命名。配对按路径稳定排序。改名伴随少量正文变化时，仅对双方完整读取、扩展名相同且正文大小受限的文件比较非空文本行：双方各有 8–200 条有效不同文本行、重合比例至少 85%，并且没有相近的竞争配对，才保守记为重命名。无法确认的仍显示为删除与新增；旧、新 SHA 都保留。两个分支指向同一 commit 时可分别保留进行中扫描，避免跨分支互相占用扫描名额；索引约束见[146 迁移](../db/migrations/146_project_scan_branch_isolation.sql)。

差异只比较两次**已索引**的路径；任一侧为部分覆盖时，页面明确提示不能把结果视为完整仓库差异。排除和未读取的文件仍可参与路径／Git SHA 比较，但不会成为代码正文证据。新扫描不继承已删除路径，报告里的证据必须来自当前扫描。

在读取新扫描正文前，已知同路径 SHA 改变的文件会优先排队；新增路径仅在基线覆盖完整时才享受优先级。详细预算与优先名额见[扫描预算](project-scan-budgets.md)。这不改变差异的计算口径：最终仍按两个索引的路径和 SHA 比较。

勾选“全量重扫”后，扫描不读取旧正文缓存，仍遵守所选文件数、总字节数及单文件上限。使用该扫描生成的分析不跨报告复用旧模块输出；失败重试仍可复用本作业已成功且经过校验的调用，避免重复计费。全量重扫依然保存与前一份扫描的差异，便于核对。相同 commit 同时只能有一个进行中的扫描；请求不同模式时返回冲突，而不悄悄合并。

当前目录级输入指纹会让变化模块重新分析、未变化模块复用；跨模块综合调用总是重新执行。静态导入、API 与 SQL 表名的分析影响范围见[增量分析影响范围](project-analysis-impact.md)。动态依赖和未索引文件仍可能漏掉，`TODOLIST.md` 的 14.9 整项仍待统一验收。
