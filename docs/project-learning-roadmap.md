# 项目学习路线：当前取数与证据边界

项目报告下方的“学习路线与个人记录”读取 `/api/project-repositories/:repositoryId/roadmap/:analysisId`。只有仓库所属账号能读取；私有仓库的路线读取和个人证据提交都经项目接口统一入口重新核验当前 GitHub 读取授权，失效或暂时无法核验时拒绝访问。接口只接受该仓库已完成的报告。路线是读取时按当前关联关系生成的视图，报告本身仍固定原 commit 和需求版本。

路线以 `project_repository_tasks` 中属于当前账号且未删除的任务为主轴。`task_dependencies` 中两端都已关联到本项目的边决定先后顺序；“建议下一步”是第一个未完成且这些已关联前置任务均完成的任务。未关联的外部依赖只统计未完成数量，不泄露其 ID 或标题；存在这类依赖、任务被手动阻塞或已完成时不会推荐为下一步，用户应在任务详情核对。任务进度和状态代表任务记录，不代表本人已掌握相关技能。

学习记录只通过明确的任务 ID 进入路线：本人 `notes.task_id` 对应任务；其 `source_session_id` 只在 `sessions.ingested_by` 也是本人时显示来源会话；本人 `experiments.task_id` 对应任务。旧记录若缺少可信的账号归属，则不进入个人路线。接口返回标题与链接，不把笔记正文、会话消息或实验输出发送给模型，也不根据这些内容推断能力。笔记或实验超过 500 条时页面明确提示证据列表已截断。

报告建议通过结论所对应的 `requirement_id` 或已接受建议的 `task_id` 找到关联任务；没有明确关系时显示“暂无明确关联”。若存在同一可信 GitHub 仓库 ID、同分支、同目标、同需求文档版本且扫描与分析范围完整、文件数相同的上一份已完成报告，按建议主题和实践文字标记“相较上次新增”。这只是建议文字变化，不是学习成效证明。旧扫描没有可信仓库 ID，不作为进度比较或当前路线的能力基线；报告基线已变化时页面提示重新核对。

每条建议可通过 `POST /api/project-repositories/:repositoryId/roadmap/:analysisId/evidence` 提交理解回答或实践过程，并可附本人提供的 HTTPS 材料链接。`project_learning_evidence` 逐条保存账号、固定报告、建议、类型、原文和时间；数据库用复合外键保证归属正确。链接仅供页面点击，不由服务端抓取。记录不可改写，路线概览展示每条建议最近三条及历史总数；本人可用同一路径的 `GET` 按建议 ID 和 `before` 游标分页读取全部记录，再为旧记录提交核验请求。它们一律是本人提交的材料，在独立核验完成前标为待核验；提交本身不产生掌握评分。

本人可对单条学习记录调用 `POST /api/project-repositories/:repositoryId/roadmap/:analysisId/evidence/:evidenceId/review-request`，明确提交独立核验请求；重复请求幂等。只有被请求的记录会进入管理员待审队列。项目所属账号无法核验本人记录；另一名管理员在 `/project-learning-reviews` 查看待审记录，私有仓库还要求审核人自己的 GitHub App 当前有该仓库读取权限。默认队列只列公开项目；私有项目由本人复制审核入口，审核人打开指定项目后才能读取。列表每页 50 条，原始记录与报告验收标准保持只读。

理解回答按“核心概念准确”和“边界情况或反例明确”两项核对；实践记录按“过程与材料可信”和“验收结果可复现”核对。审核须填写至少 20 字具体理由。两项都通过才标为 `verified`，否则为 `needs_revision`；核验不可覆盖或改写原记录，需要补充时由本人提交新记录再请求核验。审核写入 `project_learning_evidence_reviews`，与本人自述分开保存；审核账号删除后保留判断但匿名显示。页面展示待审／已核验／需补充状态与审核理由。这里的“已核验”仅表示**这条固定记录按两项标准通过人工复核**，不自动生成能力分数，也不自动修改任务或建议状态。独立账号及私有仓库授权需在实际环境验收，后续还需固定样例检验审核一致性和路线推荐质量。

路线还把已核验的具体记录整理为可复用的主题线索：必须属于同一账号、同一项目仓库的不可变 GitHub ID；跨报告复用还要求同一分支、项目目标、需求版本、稳定需求 ID，以及规范化后完全相同的建议主题和验收标准。当前报告和来源报告中的主题都必须唯一；存在重名时不跨报告复用。只有当前建议自己提交的记录可在缺少需求 ID 时显示，不能据标题向其他报告传播。分别保留最近一次理解和实践核验的原记录 ID、报告 commit 和时间；两类都有才标记为较强的前置知识线索。审核结果仍不等于整体掌握，也不能代替未完成的前置任务。超过 5000 条已核验记录或 50000 条来源建议时本次不据此作能力推断或推荐排序，页面提示范围不足。[143 索引迁移](../db/migrations/143_project_verified_learning_evidence_lookup.sql)加速按项目与账号读取核验记录。

在报告中可为未处理建议调用 `PATCH /api/project-repositories/:repositoryId/analyses/:analysisId/suggestions/:suggestionId/adjust`，保存个人调整的实践文字、验收标准和理由。原报告建议保持不可变；再次编辑须提交当前调整版本，过期版本返回冲突。接受建议创建任务或追加到已有任务时使用调整稿，已处理建议不可再改。调整稿不是独立核验记录，不会自动产生能力线索。

前置知识默认在同一报告内按规范化标题匹配唯一一条其他建议；匹配的建议须有明确关联的本人任务，才能显示任务是否均已完成。重名、无匹配、已忽略或无关联任务默认标为待人工核对。仓库所属账号可在学习路线中把某项前置知识手动映射到**本仓库已关联、归属本人且未删除**的任务，覆盖该项自动匹配；这只修正任务关联，不修改模型报告、任务状态或个人学习证据。映射任务从项目解除关联、软删除或永久删除后显示“原手动关联已失效”，不会悄悄回退为同名自动匹配；清除手动映射后才恢复自动匹配。

`PUT /api/project-repositories/:repositoryId/roadmap/:analysisId/prerequisites/:suggestionId/:index` 使用从 0 开始的前置知识位置，请求体为 `{ "taskId": "任务 ID", "expectedVersion": 0 }`；`taskId: null` 表示清除手动映射。初次映射版本为 0，此后提交接口返回的版本；并发版本不符返回 409，页面需刷新后重试。写入要求报告已完成，且分支、项目目标、需求版本、commit 仍与仓库当前基线一致；旧报告可以阅读，但页面禁用映射编辑，服务端也拒绝过期报告的写入。读取接口的每项 `prerequisiteMappings` 标明 `source: auto | manual | manual_stale`、映射版本、任务 ID 及完成状态。清除映射后版本回到自动匹配的 0；解除任务关联由数据库把映射任务 ID 置空并提高版本，防止旧编辑器覆盖失效状态。

报告目标、需求版本、仓库 ID 和 commit 未变化时，先筛出待处理且所有前置映射均有已完成任务的建议；按报告影响程度排序，同级建议再按双类核验的前置主题占比、原顺序排序。手动任务映射只改变关联任务；若前置文字在本报告唯一对应另一条建议，仍显示该建议本身可追溯的核验线索，不把手动关联的任务当作能力证据。页面展示用于排序的核验数、来源报告和时间；没有匹配记录表示线索不足，不等于未掌握。任务完成、本人自述和单类核验都不等于掌握。固定样例中推荐理由是否可信，仍须人工验收。
