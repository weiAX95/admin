# 项目学习路线：当前取数与证据边界

项目报告下方的“学习路线与个人记录”读取 `/api/project-repositories/:repositoryId/roadmap/:analysisId`。只有仓库所属账号能读取；私有仓库的路线读取和个人证据提交都经项目接口统一入口重新核验当前 GitHub 读取授权，失效或暂时无法核验时拒绝访问。接口只接受该仓库已完成的报告。路线是读取时按当前关联关系生成的视图，报告本身仍固定原 commit 和需求版本。

路线以 `project_repository_tasks` 中属于当前账号且未删除的任务为主轴。`task_dependencies` 中两端都已关联到本项目的边决定先后顺序；“建议下一步”是第一个未完成且这些已关联前置任务均完成的任务。未关联的外部依赖只统计未完成数量，不泄露其 ID 或标题；存在这类依赖、任务被手动阻塞或已完成时不会推荐为下一步，用户应在任务详情核对。任务进度和状态代表任务记录，不代表本人已掌握相关技能。

学习记录只通过明确的任务 ID 进入路线：本人 `notes.task_id` 对应任务；其 `source_session_id` 只在 `sessions.ingested_by` 也是本人时显示来源会话；本人 `experiments.task_id` 对应任务。旧记录若缺少可信的账号归属，则不进入个人路线。接口返回标题与链接，不把笔记正文、会话消息或实验输出发送给模型，也不根据这些内容推断能力。笔记或实验超过 500 条时页面明确提示证据列表已截断。

报告建议通过结论所对应的 `requirement_id` 或已接受建议的 `task_id` 找到关联任务；没有明确关系时显示“暂无明确关联”。若存在同分支、同目标、同需求文档版本且扫描与分析范围完整、文件数相同的上一份已完成报告，按建议主题和实践文字标记“相较上次新增”。这只是建议文字变化，不是学习成效证明。报告基线已变化时页面提示重新核对。

每条建议可通过 `POST /api/project-repositories/:repositoryId/roadmap/:analysisId/evidence` 提交理解回答或实践过程，并可附本人提供的 HTTPS 材料链接。`project_learning_evidence` 逐条保存账号、固定报告、建议、类型、原文和时间；数据库用复合外键保证归属正确。链接仅供页面点击，不由服务端抓取。记录不可改写，页面展示每条建议最近三条及历史总数。它们一律是本人提交、待核验的材料，不做自动正确性判断，更不产生掌握评分。后续需建立独立核验标准与流程。

在报告中可为未处理建议调用 `PATCH /api/project-repositories/:repositoryId/analyses/:analysisId/suggestions/:suggestionId/adjust`，保存个人调整的实践文字、验收标准和理由。原报告建议保持不可变；再次编辑须提交当前调整版本，过期版本返回冲突。接受建议创建任务或追加到已有任务时使用调整稿，已处理建议不可再改。调整不是能力核验，独立核验仍属于后续 14.12 工作。

前置知识默认在同一报告内按规范化标题匹配唯一一条其他建议；匹配的建议须有明确关联的本人任务，才能显示任务是否均已完成。重名、无匹配、已忽略或无关联任务默认标为待人工核对。仓库所属账号可在学习路线中把某项前置知识手动映射到**本仓库已关联、归属本人且未删除**的任务，覆盖该项自动匹配；这只修正任务关联，不修改模型报告、任务状态或个人学习证据。映射任务从项目解除关联、软删除或永久删除后显示“原手动关联已失效”，不会悄悄回退为同名自动匹配；清除手动映射后才恢复自动匹配。

`PUT /api/project-repositories/:repositoryId/roadmap/:analysisId/prerequisites/:suggestionId/:index` 使用从 0 开始的前置知识位置，请求体为 `{ "taskId": "任务 ID", "expectedVersion": 0 }`；`taskId: null` 表示清除手动映射。初次映射版本为 0，此后提交接口返回的版本；并发版本不符返回 409，页面需刷新后重试。写入要求报告已完成，且分支、项目目标、需求版本、commit 仍与仓库当前基线一致；旧报告可以阅读，但页面禁用映射编辑，服务端也拒绝过期报告的写入。读取接口的每项 `prerequisiteMappings` 标明 `source: auto | manual | manual_stale`、映射版本、任务 ID 及完成状态。清除映射后版本回到自动匹配的 0；解除任务关联由数据库把映射任务 ID 置空并提高版本，防止旧编辑器覆盖失效状态。

报告目标、需求版本和 commit 未变化时，从待处理且所有前置映射均有已完成任务的建议中，按报告影响程度和原顺序提示一条“可考虑先处理”，同时显示理由。手动映射也只读取任务当前的完成标记；这个顺序提示和任何任务完成标记都不证明用户已掌握前置知识。独立核验理解回答与实践验收仍是后续 14.12 工作。
