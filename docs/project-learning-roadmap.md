# 项目学习路线：当前取数与证据边界

项目报告下方的“学习路线与个人记录”读取 `/api/project-repositories/:repositoryId/roadmap/:analysisId`。只有仓库所属账号能读取；私有仓库还必须保有当前 GitHub 读取授权。接口只接受该仓库已完成的报告。路线是读取时按当前关联关系生成的视图，报告本身仍固定原 commit 和需求版本。

路线以 `project_repository_tasks` 中属于当前账号且未删除的任务为主轴。`task_dependencies` 中两端都已关联到本项目的边决定先后顺序；“建议下一步”是第一个未完成且这些已关联前置任务均完成的任务。未关联的外部依赖只统计未完成数量，不泄露其 ID 或标题；存在这类依赖、任务被手动阻塞或已完成时不会推荐为下一步，用户应在任务详情核对。任务进度和状态代表任务记录，不代表本人已掌握相关技能。

学习记录只通过明确的任务 ID 进入路线：本人 `notes.task_id` 对应任务；其 `source_session_id` 只在 `sessions.ingested_by` 也是本人时显示来源会话；本人 `experiments.task_id` 对应任务。旧记录若缺少可信的账号归属，则不进入个人路线。接口返回标题与链接，不把笔记正文、会话消息或实验输出发送给模型，也不根据这些内容推断能力。笔记或实验超过 500 条时页面明确提示证据列表已截断。

报告建议通过结论所对应的 `requirement_id` 或已接受建议的 `task_id` 找到关联任务；没有明确关系时显示“暂无明确关联”。若存在同分支、同目标、同需求文档版本且扫描与分析范围完整、文件数相同的上一份已完成报告，按建议主题和实践文字标记“相较上次新增”。这只是建议文字变化，不是学习成效证明。报告基线已变化时页面提示重新核对。接受和忽略建议仍使用现有报告操作；可调整的建议、理解检查及实践验收记录属于后续 14.12 工作，完成前不显示个人掌握评分。
