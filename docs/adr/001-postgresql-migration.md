# 001：本地 API 从 JSON 完整迁移到 PostgreSQL

状态：已实施（本地开发）

## 背景

原 API 将任务、会话、账号等集合一起保存在 `mock/db.json`。任务批量操作、重复实例生成、登录令牌与多人评分需要持久化约束及原子提交；单文件无法为这些关系提供可靠的数据库约束。

## 决策

开发环境使用 PostgreSQL 作为唯一运行时数据源，Docker Compose 提供开发库和隔离测试库，也可通过 `DATABASE_URL` 连接其他实例。SQL 迁移带版本号。旧 JSON 由显式命令导入空库，在一个事务中保留旧 ID 和时间、转换密码、核对集合及关联数量，并写入导入标识；原件和额外备份保留。启动时若数据库不可用、未迁移或无账号，API 报错，不自动回退到 JSON。

账号、任务及其清单／依赖／标签／资源／完成周期、重复序列、模板、工时、活动、趋势、字段历史、会话消息及标注、笔记和实验使用关系表。仅变更历史中类型不固定的 `oldValue` 和 `newValue` 使用 JSONB。聊天端用户 ID 是外部标识；消息标注关联管理端账号，账号删除后将该关联置空以匿名保留评分。

当前本地 API 为保持已有路由和任务规则，按请求在同一个 PostgreSQL 事务中读取关系表为内存工作集，执行现有领域逻辑，再将变化写回关系表。写入事务由数据库顾问锁串行化；批量修改、CSV 导入、依赖副作用及重复实例生成共用此事务。重复实例另有“序列 ID＋次数”唯一约束。认证令牌只存哈希，默认 7 天有效，退出或账号禁用／删除时撤销；HTTP 与 WebSocket 共用数据库校验。

## 影响与后续

开发和测试现在必须有可用的 PostgreSQL；JSON 文件不再接收新修改。旧数据导入只运行一次，之后使用 PostgreSQL 备份工具保管新数据。当前请求级工作集和全局写锁适合本地开发数据量，随着数据量与并发增长，应逐步把列表筛选、聚合及写入迁移为定向 SQL 查询；搜索迁移到 PostgreSQL 时应对 `%`、`_` 做字面转义后使用 `ILIKE`。本决策不代表生产部署就绪。
