# 项目分析的单次预算

创建分析时可不设置额外上限，继续受管理员每日模型预算、模型 token 配额和分钟速率限制；也可选择 30,000／60,000／120,000 token 预留上限和 $0.10／$0.50／$1／$5 美元费用上限。预算选择固定保存在分析作业，正在进行的相同扫描与模型请求会合并，返回已存在作业及其原预算。

提交前会对全部目录调用及可选跨模块调用计算保守预留：把模型输入字符数当作 token 上界，再加每次最多 2,048 个输出 token。费用使用作业创建时的模型输入、输出价格快照计算。预计预留超出所选上限时直接拒绝，不发起模型调用。每次后续调用前再以该作业历次尝试的实际 token、费用，加上剩余调用预计预留复核；不足时作业以 `ANALYSIS_BUDGET_EXCEEDED` 失败，已保存的用量不抹除。重试复用原上限并累计以前尝试的消费，若预算不足应新建分析并选择较高上限。

输入指纹和证据均校验通过的[分析结果复用](project-analysis-cache.md)调用不再预留本次 token 或费用；失败重试复制已完成输出也不重复计费。原调用已经产生的实际用量仍保留在累计预算内。

此处上限控制是否发起下一次调用，不能保证供应商对已经发出的单次调用严格只收取预估量。输入字符只是保守近似，不等于供应商实际 tokenizer；费用依赖供应商回传的用量。即使没有选择单次上限，系统每日预算和现有模型配额仍会阻止超额提交。
