# 增量分析的影响范围

从分析计划版本 4 起，服务读取该扫描保存的新增、修改、删除、重命名记录，在既有 30 个文件、30,000 字符、8 个模块预算内优先选择变化后的当前文件。对 JS／TS 源码，解析字面量相对路径的 `import`、`export ... from`、动态 `import()` 和 `require()`；`.js`／`.jsx`／`.mjs`／`.cjs` 引用可在索引中回退匹配对应 TS 源文件。Python 解析可对应到索引文件的绝对／相对 `import` 与 `from ... import`；Go 根据已读取的 `go.mod` 将本模块 import 路径映射为包内文件，同包文件也视为相关。变化文件直接导入的当前文件可优先提供上下文，并沿反向导入边逐层寻找引用它的当前文件。删除文件没有当前正文，但仍可作为图的目标，找到仍引用它的文件。优先顺序为变化后的文件、距离最近的引用方、再到直接依赖；根目录依赖或构建配置变化时，已索引目录模块均重新分析。

计划版本 5 在上述导入图中再加入明确的 API 路径边：从 `http.get('/notes')`、`fetch('/api/notes')` 等字面量请求，连接到 `pathname === '/api/notes'`、固定前缀路由正则、常见 JS／Python／Go 路由注册。路径按 `/api` 前缀和完整段边界匹配，客户端引用服务端；服务端文件变化时可沿反向边找到客户端，客户端变化时服务端可作为直接上下文。它只表示需要重新检查，不表示接口已经联通或可运行。

计划版本 6 读取扫描中可用的 `tsconfig*.json`／`jsconfig*.json`，解析 `compilerOptions.paths` 与 `baseUrl`，将字面量 JS／TS 导入别名映射到已索引的源文件，再沿同一静态影响图传播。支持精确映射及单个 `*` 通配符，并兼容配置中的注释和尾逗号；优先使用距离源文件最近的配置。配置缺失、未被扫描、`extends` 继承、Vite／Webpack 自定义别名或复杂路径映射不会推断成已知依赖。

计划版本 7 在可读配置内递归解析本地相对路径 `extends`（含本地配置数组），沿用定义 `paths` 的配置位置解析相对目标，并在同一目录有多个配置时保守合并可索引的目标。循环引用、超出仓库、仅位于 `node_modules` 或未扫描的父配置不推断；这仍不是完整的 TypeScript 模块解析器。相对配置路径的归属依据 [TypeScript TSConfig 文档](https://www.typescriptlang.org/tsconfig/#extends)；`paths` 的相对基准依据 [TypeScript 模块解析文档](https://www.typescriptlang.org/docs/handbook/modules/reference.html#relationship-to-baseurl)。计划版本 6 的旧作业继续按其原有的直接配置规则恢复。

目录模块若包含变化文件，或在上述静态图中与变化文件相关，就不会跨报告复用旧模型输出。其他模块仍须满足相同模型、连接版本、需求基线、目标、入选正文及逐行证据校验才可复用。跨模块综合调用始终重新执行。创建、恢复和重试都读取同一个扫描差异快照；旧计划版本 1／2 继续使用创建时的普通文件选择规则，版本 3 保留 JS／TS 一跳规则，版本 4 保留多语言导入规则，版本 5 保留 API 路径边规则，版本 6 保留直接配置别名规则，避免旧作业恢复时改变模型输入。

这是有上限的静态线索：不执行仓库代码，不解析仓库外配置或构建器自定义 JS／TS 别名、Python 的运行时 `sys.path`、Go 外部模块、动态拼接或挂载前缀、数据库调用关系。路由边只认支持的字面量形式，服务端被删除后若旧正文不可读，也无法还原其旧路由。逐层传播仅沿已索引且可读取文件的静态边；未扫描文件和语法不支持的边可能漏掉影响。优先级不能突破扫描预算、敏感路径排除或分析文件数／字符数上限，部分覆盖扫描也可能缺少真实影响边。页面的覆盖信息仍是判断结论适用范围的依据；更完整的跨层依赖识别和固定样例验收留在 `TODOLIST.md` 14.9。
