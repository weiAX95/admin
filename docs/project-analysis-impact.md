# 增量分析的影响范围

从分析计划版本 3 起，服务读取该扫描保存的新增、修改、删除、重命名记录，在既有 30 个文件、30,000 字符、8 个模块预算内优先选择变化后的当前文件。对 JS／TS 源码，解析字面量相对路径的 `import`、`export ... from`、动态 `import()` 和 `require()`；变化文件的直接被调用方以及直接引用变化文件的调用方也优先进入模型输入。删除文件没有当前正文，但引用它的当前文件可被选中。根目录依赖或构建配置变化时，已索引目录模块均重新分析。

目录模块若包含变化文件，或与变化文件存在上述直接导入边，就不会跨报告复用旧模型输出。其他模块仍须满足相同模型、连接版本、需求基线、目标、入选正文及逐行证据校验才可复用。跨模块综合调用始终重新执行。创建、恢复和重试都读取同一个扫描差异快照；旧计划版本 1／2 继续使用创建时的普通文件选择规则，避免恢复时改变它们的模型输入。

这是有上限的静态线索：不执行仓库代码，不解析别名、运行时动态路径、Python／Go 等其他语言或多跳依赖。优先级不能突破扫描预算、敏感路径排除或分析文件数／字符数上限，部分覆盖扫描也可能缺少真实影响边。页面的覆盖信息仍是判断结论适用范围的依据；完整的跨层依赖识别和固定样例验收留在 `TODOLIST.md` 14.9。
