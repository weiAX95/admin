# 增量分析的影响范围

从分析计划版本 4 起，服务读取该扫描保存的新增、修改、删除、重命名记录，在既有 30 个文件、30,000 字符、8 个模块预算内优先选择变化后的当前文件。对 JS／TS 源码，解析字面量相对路径的 `import`、`export ... from`、动态 `import()` 和 `require()`；`.js`／`.jsx`／`.mjs`／`.cjs` 引用可在索引中回退匹配对应 TS 源文件。Python 解析可对应到索引文件的绝对／相对 `import` 与 `from ... import`；Go 根据已读取的 `go.mod` 将本模块 import 路径映射为包内文件，同包文件也视为相关。变化文件直接导入的当前文件可优先提供上下文，并沿反向导入边逐层寻找引用它的当前文件。删除文件没有当前正文，但仍可作为图的目标，找到仍引用它的文件。优先顺序为变化后的文件、距离最近的引用方、再到直接依赖；根目录依赖或构建配置变化时，已索引目录模块均重新分析。

目录模块若包含变化文件，或在上述静态导入图中与变化文件相关，就不会跨报告复用旧模型输出。其他模块仍须满足相同模型、连接版本、需求基线、目标、入选正文及逐行证据校验才可复用。跨模块综合调用始终重新执行。创建、恢复和重试都读取同一个扫描差异快照；旧计划版本 1／2 继续使用创建时的普通文件选择规则，版本 3 保留 JS／TS 一跳规则，避免旧作业恢复时改变模型输入。

这是有上限的静态线索：不执行仓库代码，不解析 JS／TS 别名、Python 的运行时 `sys.path`、Go 外部模块、动态路径或 HTTP／数据库调用关系。逐层传播仅沿已索引且可读取文件的静态边；未扫描文件和语法不支持的边可能漏掉影响。优先级不能突破扫描预算、敏感路径排除或分析文件数／字符数上限，部分覆盖扫描也可能缺少真实影响边。页面的覆盖信息仍是判断结论适用范围的依据；跨层 API 依赖识别和固定样例验收留在 `TODOLIST.md` 14.9。
