# 项目分析结果复用

计划第 11 版的模块输入指纹包含既有已接受建议候选快照；候选文字或顺序变化时不能复用旧模块输出。历史计划版本沿用各自保存的输入格式。

同一仓库后续分析可复用已完成报告中的目录模块输出。服务为每次模块调用记录输入指纹；指纹涵盖模块名、实际入选的文件内容及路径、项目目标、需求正文和固定版本、模型与连接版本、模型参数和提示词。提交 commit 的 SHA 不参与指纹，因此未变化的模块可以跨 commit 复用。跨模块综合调用涉及多个模块的关系，本阶段始终重新执行，不跨报告复用。

复用前，服务用**当前扫描入选文件**重新校验旧输出的结构和每条证据的路径、行号及逐字原文。任一条件不符就重新调用模型。只有启用并带版本号的数据库模型连接才使用跨报告缓存；环境变量连接和旧作业没有可靠连接版本，不参与该缓存。连接配置变化后，新作业的指纹不同；运行期间连接版本变化，后续调用停止，已发出调用的结果也不进入可复用缓存。

命中的输出在创建作业时复制为该作业的已完成调用，保存来源报告 ID 和 commit。复制调用的本次 token 与费用为零，不占本次模型调用预留。失败重试可复用同一作业上次尝试中已完成且重新校验通过的调用；以前尝试**实际发生**的 token 和费用仍计入该作业的累计预算，不会清零。页面显示复用调用数和各模块来源 commit。

复用是静态分析输出的复用，不代表代码已运行或需求已验收。旧报告没有输入指纹，不能反推补建缓存；删除文件不会出现在新扫描的文件集合中，其旧证据也无法通过当前扫描校验。手动[全量重扫](project-scan-changes.md)会绕过跨报告输出缓存；同一作业失败重试仍可复用已完成调用。变化模块及其可静态解析的多跳导入或明确 API 路径关联模块也会跳过旧输出，规则见[增量分析影响范围](project-analysis-impact.md)。动态依赖及未索引路径仍可能遗漏，因此 14.9 整项保持未完成。
