# 会话导出

会话列表支持跨分页复选多条会话。选中后可下载 Markdown 或 JSON；单次限 1–50 条，超出后导出按钮禁用。清空选择不会影响列表和搜索。下载期间按钮显示处理中，失败时给出错误提示。

`POST /api/sessions/export` 使用管理端登录令牌，请求体为 `{ "ids": ["会话 ID"], "format": "json" | "markdown" }`。所选 ID 必须存在且不可重复；任一缺失则整批返回 404，不生成不完整文件。响应是带 `Content-Disposition: attachment` 的下载文件，并设 `Cache-Control: no-store`。JSON 含导出时间、按所选顺序排列的会话、主题、消息数、聊天端用户 ID、创建与更新时间，以及按原顺序排列的消息 ID、角色、时间、完整正文和每条标注。Markdown 以会话和消息为章节，使用长度足够的代码围栏保留正文中的反引号和换行，并列出标注。两种格式都保留空会话。

会话本身沿用当前共享查看权限：所有已登录管理端账号可导出。普通成员获得完整评分和标签，但标注中的评分账号 ID 不返回；管理员的 JSON 包含该 ID。聊天端用户 ID 是外部身份，不是管理端评分账号。接口对三张会话相关表执行一次只读事务和批量查询，不逐条调用会话详情接口，也不进入旧接口的整库加载锁。

本地验收命令：`npm run benchmark:session-export`。2026-10-11 在 10 核／16 GB macOS、Node 22.23.2、Docker PostgreSQL 18.6 的回环连接上，构造 50 个会话、每会话 20 条消息、总计 1,000 条消息，导出 JSON 文件约 566 KB，连续执行 10 次。计时从发送 HTTP 请求到接收并解析完整 JSON：中位 43 ms、最大 61 ms，低于 3 秒。数据库建库、种子写入、登录和浏览器保存文件不计入。页面显示由用户验收；生产主机和真实数据分布需单独测量。
