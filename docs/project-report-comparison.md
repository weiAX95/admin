# 项目报告历史与对照口径

项目分析记录按创建时间和 ID 倒序分页，每页最多 30 条；页面可继续加载更早记录。每条记录显示创建时间、commit、模型、状态和扫描覆盖，报告详情仍以固定 commit、分支和需求版本读取，不用当前仓库状态改写旧结论。

“两次报告对照”只接受同一账号所属仓库内两份已完成报告。服务端按固定需求 ID 配对结论；某个需求在任一报告中有零条或多条结论时不做一对一状态比较，避免误配。状态变化显示为新增完成线索、可能退化、新发现缺口、缺口改善线索或一般变化，同时并列展示两份报告各自固定 commit 的原始证据链接。建议变化只按主题和实践文字归一化比较，不代表建议已完成。

分支、需求版本或项目目标不同，无法安全配对需求结论。任一报告部分覆盖，或进入分析／可用文件数量不同，页面展示可比性限制；可配对的变化仍作为待复核线索显示。页面不提供“进度增长百分比”，因为静态阅读、模型判断和不同扫描范围都不能证明运行验收通过。人工校正保存在各自报告中，原始模型结论与人工判断应分别查看。

接口：`GET /api/project-repositories/:id/analyses?before=<分析 ID>` 返回 `items` 与 `nextCursor`；`GET /api/project-repositories/:id/analyses/compare/:olderId/:newerId` 返回比较限制、可配对状态变化及建议文字变化。两者都检查当前账号的仓库归属。
