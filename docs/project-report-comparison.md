# 项目报告历史与对照口径

项目分析记录按创建时间和 ID 倒序分页，每页最多 30 条；页面可继续加载更早记录。每条记录显示创建时间、commit、模型、状态和扫描覆盖，报告详情仍以固定 commit、分支和需求版本读取，不用当前仓库状态改写旧结论。

“两次报告对照”只接受同一账号所属仓库内两份已完成报告。服务端按固定需求 ID 配对结论；某个需求在两份报告中各恰好有一条结论时，状态变化继续显示为新增完成线索、可能退化、新发现缺口、缺口改善线索或一般变化。若状态相同，但标题、说明或证据类型／路径／行号／原文／Git blob SHA 不同，则另列为「同状态的文字与证据变化」，不改变原状态变化判断。两处均并列展示两份报告各自固定 commit 的原始证据链接。建议变化只按主题和实践文字归一化比较，不代表建议已完成。

无法一对一配对的结论另列「未能安全配对」：仅新报告出现、仅旧报告出现、同一需求在任一侧有多条、缺少稳定需求 ID，以及仓库身份、分支、项目目标或需求基线不同。后一种情况整组并列保留两份报告原始结论，且不生成配对状态变化；其余情况按需求或无 ID 分组，不凭文本相似度猜配对。每组显示具体待复核原因和原始证据。「仅新报告出现」不等于新增实现，「仅旧报告出现」不等于问题已解决。新增的只读复核数据不参与自动进展通知；通知仍只根据原有可比范围内的状态变化和高影响新建议生成。

分支、需求版本或项目目标不同，无法安全配对需求结论。任一报告部分覆盖，或进入分析／可用文件数量不同，页面展示可比性限制；可配对的变化仍作为待复核线索显示。页面不提供“进度增长百分比”，因为静态阅读、模型判断和不同扫描范围都不能证明运行验收通过。人工校正保存在各自报告中，原始模型结论与人工判断应分别查看。

接口：`GET /api/project-repositories/:id/analyses?before=<分析 ID>` 返回 `items` 与 `nextCursor`；`GET /api/project-repositories/:id/analyses/compare/:olderId/:newerId` 返回比较限制、原有 `changes`、新增只读 `findingReview.sameStatusChanges`／`findingReview.unmatchedGroups` 及建议文字变化。两者都检查当前账号的仓库归属。

未关联明确需求的新版结论额外保存 `F-` 功能线索 ID，使用目录模块、规范化标题及证据文件路径计算；行号与 commit 变化不改变该 ID。标题或文件移动会产生新 ID，同名同路径的不同功能仍可能共用 ID，因此对照页仅展示供人工核对，不自动把它当成进度配对依据。旧报告保留空值，不追溯推断。
