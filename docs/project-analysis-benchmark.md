# 项目分析固定样例与人工评审

本地夹具位于 [`tests/fixtures/project-analysis-sample`](../tests/fixtures/project-analysis-sample)。测试会从 `current/` 构造一个真实 Git 仓库，先加入 `prior/src/archive.js` 提交旧版本，再删除该入口形成当前版本；作者与提交时间固定。扫描器通过受控 GitHub 响应读取当前 commit 的目录和 blob，不执行仓库代码，也不依赖外网。

[`labels.json`](../tests/fixtures/project-analysis-sample/labels.json) 是人工标注清单。这里的“已实现”表示当前源码及测试存在对应线索，**不表示已经运行验证**；“未发现实现”只适用于本夹具完整扫描的当前 commit。样例文件保留了 README 的错误声明，以检验文档不能单独证明功能。

| 需求 | 人工标签 | 主要陷阱 |
| --- | --- | --- |
| REQ-001 | 已实现线索 | 创建函数与相关测试可定位 |
| REQ-002 | 部分实现线索 | 改名保留 ID，但没有拒绝空标题 |
| REQ-003 | 未发现实现 | 当前完整扫描中没有 CSV 导出 |
| REQ-004 | 待验证 | 只有 README 声称邮件提醒 |
| REQ-005 | 部分实现线索 | 重复 ID 被静默忽略，且没有对应测试 |
| REQ-006 | 未发现实现 | 旧 commit 有归档入口，当前 commit 已删除 |

运行 `node --test tests/project-analysis-benchmark.test.mjs` 会创建夹具、扫描固定 commit、用人工构造的报告验证结构和证据，再注入错误报告，确认评分器能计出误判、漏判、旧证据与缺失建议。已有报告可导出为 JSON 后运行 `npm run benchmark:project-analysis -- /绝对路径/报告.json`；输出逐需求结果与计数，非零错误返回非零退出码。报告必须来自**该夹具生成的当前 commit**，其他仓库报告会显示 commit 不匹配。命令不会替代人工阅读报告。

M1 正式验收前暂定六个样例、错误上限为：无证据或旧证据 **0**、把文档声明误报为已实现／部分实现 **0**、漏掉明确存在的实现 **0**、其余状态不符 **0**、缺少必要实践建议 **0**。这是此固定夹具的门槛，不代表真实项目的通用准确率。应至少记录模型 ID、价格配置、扫描 commit、需求版本、原始报告 JSON、每例人工意见和最终审阅人。真实模型及真实 GitHub 网络连通评审尚未执行，不能据模拟报告勾选 14.4 或 14.5 整项。

人工评审记录模板：

| 字段 | 填写值 |
| --- | --- |
| 评审日期 / 审阅人 | 待填写 |
| 样例当前 commit / 需求版本 | 待填写 |
| 模型 / 连接 / 价格快照 | 待填写 |
| 报告 ID / 原始 JSON 路径 | 待填写 |
| REQ-001 至 REQ-006 的实际状态、证据和建议 | 逐项填写 |
| 误判 / 漏判 / 无证据 / 旧证据 / 建议缺失计数 | 待填写 |
| 结论与需修复的问题 | 待填写 |
